# Codex Taskbar V3 视觉基准与逐模块验收

## 目的与范围

本文件把 UI 设计稿转化为可执行约束。开发必须按“一个模块完成并截图验收后，再进入下一个模块”的顺序进行，禁止为了赶进度同时改任务栏、自动浮窗、详情卡与设置页。

本版本仅支持官方登录数据源。所有数字必须来自既有的官方 App Server 或只读本机 SQLite 后备，设计稿中的数字只是视觉样例，不能写入生产显示。

## 统一视觉令牌

| 项目 | 硬性约束 |
| --- | --- |
| 基底 | 任务栏采用近黑石墨 `#101015`；详情与设置沿用统一的深海军蓝玻璃 `#081225`。三者都只允许一层低对比细描边 |
| 边框 | 单层蓝灰细边，约 `#62799F` 的 35%–55% 不透明度；禁止多重透明描边、外轮廓残影或阅读遮罩 |

### 流式能量边界动态细则

1. GIF 与 MP4 的可复用特征是：深黑椭圆胶囊中，左侧的**已消耗色彩填充区域本身是动态流场**，其末端是一条竖直但不规则的发光流体边界；边界附近有柔光、细小亮点和向前推进的质感。它不是横向正弦水面、闪电，也不是用半透明竖线堆出的条纹。
2. 填充宽度严格表示**已消耗比例**：`consumed = 100 − remaining`。0% 消耗时边界贴左，100% 消耗时边界推进至右端；右侧大字号继续显示“剩余 xx%”。不得把剩余值直接当作填充宽度。
3. 5 小时层与 Weekly 层必须在一枚胶囊中重叠，不能拆成上下两条：5 小时为低饱和紫色底层，Weekly 是高亮前层。两个值相同时前层覆盖底层；值不同时，底层仅在前层边界附近或左侧以低对比方式可见。5 小时不存在时完全隐藏底层，不留下空层或占位。
4. 前层色相反映状态：执行青蓝、推理蓝紫、空闲/完成青绿、等待琥珀、失败柔红、未知中性蓝灰。状态色只影响 Weekly 的前景流体；5 小时仍保持柔紫。详情卡的额度预览以后也必须复用该映射。
5. 运动由 64–96 个沿 Y 轴的平滑采样点构成，真实边缘只以约 ±2–4 DIP 的低振幅连续涨落；已消耗区域内要有多层低对比、缓慢从**左向右翻滚**的发光流体面，新波带从左端进入并在额度前沿消散。浪抵达前沿时，允许一层不参与数值计算的淡色薄水层短暂越过真实边缘约 5–8 DIP，并以连续泡沫外缘渐淡、回收。用互不整除的低频连续扰动模拟自然随机性，禁止短周期归零、跳变、散粒子或密集扫描线。正常模式始终以约 60 FPS 刷新**整个流式胶囊脏区**；降低动画设置下使用静态相位。

## 迭代顺序与阶段门禁

### 阶段 A：任务栏本体（当前唯一允许修改的模块）

目标：在副屏任务栏中呈现一枚紧凑、可点击、单一胶囊式双层流式额度组件。

功能数据接线：

- 今日消耗：仅官方日汇总或本机只读增量账本；无数据为 `--`，不得回退为当前任务 Token。
- 缓存命中：仅输入与缓存输入同时可信时显示；否则为 `--`。
- Credits：官方原始余额，仅在 5 小时额度耗尽后显示；无 5 小时窗口时，Weekly 耗尽后显示。它不是美元，最多两位小数。
- 右侧额度：Weekly 始终优先；5 小时窗口存在时才显示第二行。百分比来自官方额度快照，不伪造数值。
- 活动颜色：执行为青蓝、推理为蓝紫、空闲/完成回落为青绿、等待为琥珀、失败为柔红；不再额外显示状态文字或状态灯。

视觉验收：

1. 一个胶囊、一个视觉平面；绝不出现上下分区、独立进度条、横向水面、竖条纹、左侧阅读遮罩或第二个透明轮廓。
2. 额度填充用“已消耗宽度”推进，填充区域和边缘都必须动态：填充内部为低对比流光，前沿为连续的竖直流式边界。不能退化成静态填色加一条线、闪电或高频噪点。两层边界在同一平面重叠，5 小时缺失时只保留一条前景边界。
3. 文本锚点固定：左上今日、左下缓存，中部 Credits（仅满足条件时），右上显示 Weekly **剩余**百分比，右下显示 5 小时**剩余**百分比；文字位于流体层上方。
4. 默认宽度为 440px，呈紧凑椭圆比例；旧配置中恰为历史默认 320px、520px 或 620px 的值自动迁移，用户显式设置的其他宽度保持不变。
5. 单击任务栏弹出详情卡；右键菜单可用；主任务栏本体不可背景穿透。
6. 在真实 release 中截图，与两张设计稿并排审查；未达成前不得开始阶段 B。
7. 动态截图验收需采集至少相隔 300ms 的两帧：流式边界和微高光的位置应改变，文字、填充宽度和椭圆边界不可抖动；空闲状态在过渡完成后 CPU 不应因动画持续增长。截图必须与 GIF 的“竖直发光边界”并排审查。

### 阶段 B：自动消费浮窗（A 通过后）

目标：只在可信消耗增长时，在任务栏上方短暂上浮一张紧凑的横向深色信息卡。卡片底边正中必须有一个朝下的小尖角，明确指向下方的任务栏组件。

显示顺序固定为：输入、缓存输入、输出、命中率、预计金额、额度消耗。它们全部是“本次 Token 消耗”的同一轮快照，不显示今日累计、5 小时重置、Weekly 重置或日期。官方未提供本轮美元估算时显示 `--`，不自行按 Credits 换算；“额度消耗”仅在相邻官方额度快照可计算可靠差值时显示，否则为 `--`。触发条件仅为官方 Token 正向增量或官方额度实质下降，自动隐藏约 4 秒。

验收：使用模拟官方增量和真实运行各截图一次；轮询、SQLite 后备和状态色变化均不得误触发。

### 阶段 C：详情卡（B 通过后）

目标：大尺寸深色玻璃卡，完整但不拥挤。

必含真实数据区：

- 双层额度预览、5 小时和 Weekly 的重置时间；
- 今日消耗大数值、今日输入/缓存/输出/缓存命中；
- 账户、订阅/认证、Credits 原始余额、重置券精确到期时间、历史总消耗；
- 官方明确给出时才显示 API 等价估算金额，并显著标为“估算、非订阅账单”；
- 连续平滑的 7 日趋势曲线。无可用历史时显示解释性空状态，不显示伪造曲线；
- 趋势点悬停交互与 K/M 自动进位。

官方数据接线及缺失策略：

| 展示项 | 首选数据 | 可接受后备 | 不可接受做法 |
| --- | --- | --- | --- |
| 5 小时 / Weekly 额度、重置时间 | 官方 Codex App Server rate-limit 快照 | 仅可显示最近可信官方缓存并标注缓存 | 由 Token 或 Credits 反推额度 |
| 账户、订阅 / 认证、Credits、重置券 | 官方账户快照 | 无；缺失则显示 `--` 与可理解提示 | 把 Credits 当美元或伪造余额 |
| 当前 / 本次 Token 构成与官方预估金额 | 官方线程 usage | 只读 SQLite 的结构化累计 Token 可作本机统计，但必须标注非官方完整账单 | 读取 `item_json`、提示词或线程正文 |
| 今日与历史消耗、7 日曲线 | 官方日桶 / 账户 usage | 本机增量账本仅作当天部分统计，趋势缺失时显示空状态 | 用当前任务 Token 或示例图数据补全历史 |

若官方端某字段在实际协议中确实未返回，必须先记录一次脱敏诊断（字段是否存在、时间新鲜度、来源健康状态），再决定使用上表后备或显示缺失态；不得为了“界面完整”编造数值。

验收：官方模拟完整数据、官方真实不完整数据、无 5 小时窗口、额度耗尽并显示 Credits 四个场景截图。

### 阶段 D：设置页（C 通过后，一页一页验收）

目标：同一 `codex-taskbar.exe` 进程内按需打开的集成式窗口。关闭主程序必须同时关闭设置页；关闭设置页不能退出任务栏。

页序：概览/官方账户、任务栏布局、弹出行为、刷新与数据、日志与导出。每页先完成视觉稿对照、再接入配置读写和保存后的主程序热重载。

验收：每页在 100%、150%、200% DPI 截图；点击、键盘焦点、滚动、保存、恢复默认、重新打开均需验证。

设置功能测试：每个设置项须有“修改 → 保存 → 主任务栏热重载 → 重启后保留”的测试；任务栏宽度、圆角视觉比例、左右停靠、副屏优先、TrafficMonitor 间距、动画降低、显示项可见性、自动浮窗行为和日志等级均不能只做 UI 外壳。

## 运行与资源验收

- 每个阶段完成后先运行 `cargo fmt --all -- --check`、相关 crate 测试、Clippy；阶段结束再运行 workspace 全量测试。
- 必须构建 `cargo build --release -p codex-taskbar` 并关闭旧版主进程后启动新 release，不能用 debug 或设计预览冒充真实验收。
- 每次 UI 变更后必须通过截图核对本阶段设计稿，再记录“符合/不符合/下一项改动”。
- 常驻窗口不得高频写盘；SQLite 只读轮询保持现有节流；空闲时不维持海浪动画计时器。
- 不记录 API Key、账户 token、线程 ID、提示词、`item_json` 或原始服务端错误。
