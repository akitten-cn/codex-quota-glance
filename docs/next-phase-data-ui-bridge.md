# 下一阶段：真实数据快照与 WebGL 任务栏接入

## 目标

在把已确认的流体任务栏、消耗弹窗、详情卡片和设置页接入桌面程序前，先建立一份可验证的统一快照。UI 只消费该快照，禁止直接访问 Codex SQLite、`auth.json`、App Server 原始 JSON 或网络。

本阶段只支持官方登录。New API、模型价格、API Key 与相关设置不再进入新 UI 或新快照。

## 宿主边界

```text
Rust 常驻核心
  ├─ Codex App Server：官方账户、额度、Credits、账户日用量
  ├─ Codex SQLite（mode=ro）：桌面活动状态与本机累计 Token 后备
  ├─ 状态仲裁 / 本机聚合账本 / 日志 / DPAPI / 定位 / 托盘
  └─ WebView2 渲染面
       ├─ 常驻任务栏（WebGL 流体，requestAnimationFrame）
       ├─ 消耗弹窗与详情卡片（按需显示）
       └─ 设置窗口（按需创建，关闭即释放）
```

WebView2 只加载随程序打包的静态资源；不使用 Electron、不运行 Node、不允许页面自行请求官方接口。Rust 到页面只发送经过序列化的只读快照与设置投影。

## `TaskbarSnapshot` 约束

新快照必须带 schema 版本、观测时间与各字段可用性。字段缺失使用 `null`/明确状态，禁止以 `0`、空 Credits 或上一次窗口伪装为当前数据。

| UI 信息 | 来源 | 允许降级方式 |
| --- | --- | --- |
| 5 小时、7 天额度与重置时间 | `account/rateLimits/read` / 更新事件 | 不可用时隐藏对应额度，不画旧进度 |
| Credits / 余额 | 官方额度快照 | 仅在规则满足时显示原始单位；不能换算为美元 |
| 重置卡 | 官方 `rateLimitResetCredits` | 不可用时显示 `--`，不伪造数量 |
| 官方账户、订阅、日用量、服务端金额估算 | App Server 账户/用量端点 | 独立标记为缓存或不可用 |
| 当前运行状态 | App Server 具体事件优先；SQLite 低置信后备 | 无可靠证据为 `unknown`，但绝不让 Unknown 阻塞 SQLite |
| 今日本机 Token / 历史趋势 | 只读 `state_*.sqlite` 线程累计的正向差值 | 首帧只建基线；缺失字段显示 `--` |

### 额度与余额显示规则

1. 7 天额度存在时显示；有 5 小时额度时叠加显示。
2. 5 小时额度缺失是“官方未提供”，不是读取失败，任务栏自动隐藏该层。
3. 有 5 小时时，5 小时用尽后显示 Credits；没有 5 小时时，7 天额度用尽后显示 Credits。
4. Credits 是官方原始单位，除非服务端明确提供货币金额，否则只显示两位小数，不默认当作美元。

### 活动状态仲裁

1. App Server 只在给出具体状态时获得 10 秒租约；自启动的 App Server 不能永久遮蔽桌面 Codex。
2. SQLite `thread_history_*.sqlite` 的 `started_at`/`completed_at` 要先识别秒或毫秒。当前已确认真实数据库存在 Unix 秒值。
3. `inProgress` 且安全 item 类型为 `reasoning` 显示推理中；`commandExecution`、`fileChange`、工具类型显示执行中；没有 item 类型时只能低置信推理中。
4. 无进行中 Turn 时应回到空闲；完成和失败只保留短暂过渡状态，随后回空闲。
5. 日志只记录归一化枚举、来源健康度和时间单位判定，不能记录线程 ID、标题、Prompt、item JSON 或命令正文。

### 本机账本与写盘

- 只保存 `日期 → 总 Token + 24 个小时桶`，不保存线程标识、模型、对话或正文。
- 每个 SQLite 轮询只在内存合并；首次观测和累计回退只更新基线。
- 账本 dirty 后最短 5 分钟批量原子写入一次；进程正常退出时最多再写一次。
  **已实现：** `local-usage-ledger.json` 先写同目录临时文件再替换；没有增量时不写盘。
- 历史保留由设置控制（30 / 90 / 365 天）；清理只删除本机聚合记录，必须二次确认。

## 验收矩阵

在接 UI 前，必须以 fixture 覆盖以下情况：

1. 双额度、仅 7 天、5 小时耗尽、7 天耗尽、Credits 未知/无限。
2. 推理、执行、等待用户、完成、失败、空闲、SQLite 不可读。
3. 秒时间戳与毫秒时间戳的 `inProgress`，以及超过硬租约的遗留 Turn。
4. 今日 Token 首帧、正向增长、线程累计回退、新线程、跨天。
5. 官方日用量、服务端金额缺失、缓存命中计算所需字段缺失。

真实验收必须在实际 Codex 任务中观察至少一次执行中、一次完成后空闲；不能只凭单元测试宣布状态修复完成。

## 实施顺序

1. 将现有 `MonitorState` 投影为版本化 `TaskbarSnapshot`，并为所有额度/状态规则补测试。
2. 完成本机账本限速持久化、保留和清理接口。
3. 在开发模式通过 fixture 驱动快照，验证任务栏、弹窗、详情三种状态。
4. 用同一快照接入 WebView2 流体任务栏，完成真实 Codex 状态截图验收。
5. 再接入详情、设置和更新器；GitHub Actions 发布与自动更新最后实现。
