# 官方登录版 UI 重构 V2

## 目标与范围

本阶段将 Codex Taskbar 收敛为 **官方登录专用** 的 Windows 软件，重做任务栏、
详情卡片和设置窗口三套界面。任务栏不再透明穿透：它是任务栏上的一个深色、可
点击的紧凑状态组件；详情和设置窗口均采用同一套深色现代视觉语言。

不恢复 New API、第三方余额、API Key、模型价格或本地“当前任务 Token”展示。
继续使用 Rust + Win32 + Direct2D（常驻任务栏和详情）及按需 Rust 设置窗口，
不引入 Electron、WebView2 或 TypeScript。

## 已确认的数据语义

| 用户可见名称 | 数据来源 | 展示规则 |
| --- | --- | --- |
| Weekly / 5h 订阅额度 | 官方 Codex App Server | 实时百分比；5h 不存在时不留占位。 |
| Credits 余额 | 官方 Credits 的 `balance` 原值 | Credits 点数；可解析数字固定显示两位小数，绝不当成美元。 |
| USD 估算 | 官方线程用量的 `estimatedUsageUsdMicros` | 仅在官方明确返回时显示，是计划估算，不是 Credits 余额或最终账单。 |
| 今日消耗 | App Server 日聚合，或 SQLite 结构化累计的本机增量账本 | 官方优先；本机值仅统计程序运行后观察到的正向增量，并标注“本机捕获”。 |
| 缓存命中率 | 官方 Token 快照 | 只在分子分母齐备时显示；本机累计没有该明细，明确标为不可用。 |
| 活动状态 | App Server 活动事件优先，SQLite `inProgress` 后备 | 不显示状态文字或状态灯；由前景海浪的颜色、速度和振幅表达。 |

### Credits 余额与 USD 估算

`credits.balance` 是官方后端返回的 Credits 点数余额。Credits 并不是现金余额，
当前协议也没有给出 Credits 与 USD / CNY 的固定兑换率，因此不可将其标记为美元或
自行换算。Codex 桌面端在部分工作区显示的美元是计划成本估算，和 Credits 余额是
不同指标。

格式化规则：原值可解析为十进制数时，详情显示 `余额 12.50`（四舍五入至两位）；
非数值或协议将来改为带单位文本时原样安全截断显示。任务栏使用短格式
`Credits 12.50`，详情卡片使用 `余额 12.50`。当官方没有返回美元估算时，
只保留该两位小数余额，不展示 `$0.00`、汇率或任何推导金额。

只有 App Server 明确返回 `estimatedUsageUsdMicros` 时，详情卡片才可另列
`美元估算 $0.02`，并附“估算，非账单”说明；不得由 Credits 余额、模型价格或
用户的订阅档位反推。

仅在以下条件显示余额：有可用余额，并且有 5h 时 5h 已耗尽；无 5h 时 Weekly 已
耗尽。其它时间不占任务栏空间。

### 今日 Token

“当前任务 Token”从任务栏、详情 Hero、明细和图表中全部移除。新的首选指标是
“今日消耗”。为防止误报：

1. 优先接受 App Server 明确提供的 `today` 聚合；
2. 官方没有该数据时，只允许以 `state_*.sqlite` 的结构化 `tokens_used` 正向差值做本机捕获；首帧、新线程和回退值只建立基线；
3. 本机账本不读 `item_json`，不写线程 ID、提示词或路径，当前仅驻留内存，不增加磁盘写入；
4. 缺少任何来源时显示“等待捕获”空状态，绝不以最近线程、账户历史 `daily_usage` 或“最近一天”冒充今日。

## 活动状态修复

当前 `thread_history` 后备只允许 30 秒的安全 item 心跳。长时间的推理、定义自定义
交互组件等阶段可能不写入新的 item，于是仍是 `inProgress` 却被过早降级为 Unknown。

V2 改为两段式租约：

1. 有 App Server 的明确活动事件时，它在 10 秒短租约内优先；没有续约时 SQLite 后备重新接管，避免自启动 service 的一次旧事件永久遮蔽桌面任务；
2. `completed_at` 为空且状态是 `inProgress` 时，安全 item 心跳在短租约内决定“执行/
   思考”；短租约过期后，只要同一数据库仍有新近安全写入则续约；
3. 连续长任务允许以 `inProgress` 保持低置信活动，直到显式终态或超过可配置的硬上限；
   超过硬上限才显示中性灰蓝静态浪，不能永久显示假活动；
4. 状态由前景海浪表达：思考紫蓝低频、执行青蓝较快、等待金色余波、完成/空闲短暂
   绿色涌动后静止、失败红色低亮、未知灰蓝无流动；任务栏没有状态文字或独立状态灯。

诊断日志只记录活动枚举、租约分支和时间单位；不记录线程 ID、提示词、工具参数或
SQLite 正文。

## 统一视觉方向

参照用户提供的“黑色圆角胶囊 + 亮色流式能量边界”风格，但不直接复制图像。

- 底色：近黑蓝 `#11151E`，实体、不透明；
- 流式层：根据额度窗口在蓝 / 紫 / 绿之间选择一条缓慢移动的粒子/噪声渐变，不用
  高频闪烁，不读写磁盘；
- 文本：高对比暖白，数字为粗体等宽数字；
- 动效：常规 20 FPS 上限，仅动态灯和流式边缘标脏重绘；“减少动画”关闭流动与灯的
  连续呼吸；
- 所有组件保持无障碍命中区，任务栏组件不再使用 `WS_EX_TRANSPARENT`；不再绘制独立状态灯。

### 流式进度组件

用户参考图的核心是“边界持续流动的长胶囊”，不是圆形本身。V2 将用一个共享外壳内
的**同一水域双层叠浪胶囊**替换现有嵌套圆环：Weekly 前景海浪与 5 小时底层海浪处于
相同的 X/Y 水域并真实相互覆盖，绝不是上下两条水道或两个分离胶囊。进度方向统一为
**已消耗**：剩余 0% 时水面拉满，避免“空条究竟代表没有数据还是额度耗尽”的歧义。

```
┌──────────────────── 同一片水域 ────────────────────┐
│ 今日 42.8K · 缓存 78% · CR 12.50（条件）     58% 每周 │
│ 紫色 5 小时底浪 ～～～～～ 被 青色 Weekly 前浪 ～～～～ 覆盖 │
│                                      5小时 21%        │
└────────────────────────────────────────────────────┘
```

- 一个宽实体容器只有一片海浪水域；今日、缓存、条件 Credits 与百分比全部浮在水域
  内部的半透明暗色阅读安全区，不再存在外置左侧信息轨、上下分栏或多个独立胶囊；
- 前景：Weekly 海浪，颜色/速度反映活动状态；底层：5h 紫色稳定海浪。两层波面共享
  裁剪区域，并以不同相位交错，不用直线分隔；
- 右侧：大号 Weekly 剩余百分比与较小 5h 百分比，使用等宽数字；
- 订阅额度尚有余额：蓝紫流；5h 缺失时只渲染 Weekly，不留空轨；
- 订阅额度耗尽而 Credits 可用：主轨保持拉满，色彩转为琥珀流，文字切换为
  `CREDITS · CR 12.50`。Credits 没有“初始总量”时不伪造百分比；
- 订阅额度与 Credits 都不可用：主轨拉满并降为红灰静态，不展示错误长文本。

这使用户在任务栏上一次就能区分“订阅还剩多少”和“已经进入 Credits 消耗模式”。

海浪本身取代状态灯。上层 Weekly 海浪的颜色、振幅和速度承担“活动状态”语义：思考
为低频紫蓝波，执行为较快的青蓝浪峰，等待用户为缓慢金色余波，完成/空闲为短暂绿色
涌动后静止，失败为红色低亮静态波，未知为灰蓝无流动。下层 5 小时海浪保持紫蓝，
用于一眼区分两个额度窗口。Credits 模式用外壳/文字琥珀色标记来源，不抢占上层的
活动颜色。

### 渲染与资源架构

参考作品采用 WebGL2 + GLSL 是合理的网页实现，但本软件若为该效果引入 WebView2
或 Chromium，会与低内存、低磁盘写入、小安装包的目标相冲突。V2 选择 Windows
原生 GPU 路径：

| 层 | 技术 | 原因 |
| --- | --- | --- |
| 宿主/交互/多屏定位 | Rust + Win32 | 保留已有可靠的任务栏嵌入和副屏几何能力。 |
| 流式进度 | Direct2D 参数化双层波带 | 以 72 个轻量垂直波带构成同坐标水域；无浏览器运行时、无需着色器缓存或额外 GPU 设备。 |
| 文字、详情卡、图表 | Direct2D / DirectWrite | 小、清晰、现有命中测试和 DPI 逻辑可复用。 |
| 设置窗口 | Rust + Slint（软件渲染） | 按需进程，保持可点击/可滚动，不让设置页常驻占 GPU 或内存。 |

当前波面直接由 Direct2D 在现有 layered surface 中绘制；常驻进程不需要 WebGL2、
JS、浏览器子进程、大纹理或着色器缓存。若后续引入 HLSL，也只能替换这一绘制实现，
不能改变数据、交互和低写盘约束。

资源预算（发布验收门槛）：主程序空闲 CPU 小于 0.3%，不因 UI tick 写盘；设置窗口
关闭后不留驻留进程；两个发布 exe 合计不超过 7 MB（当前约 5.2 MB）；流式动画仅在
可见且未开启“减少动画”时以最多 20 FPS 更新。日志、今日账本和配置均通过批量、
原子、小文件写入，绝不随帧或 Token 微增量写盘。

### 一套设计系统，而非四个页面拼接

任务栏、自动快览、详情卡和设置窗口共用同一组设计 Token：深蓝黑 Surface、蓝紫
订阅流、琥珀 Credits 流、活动灯颜色、16/12/9 px 圆角层级、等宽数字、相同的 150 ms
交互缓动与 20 FPS 动效上限。Rust 渲染器和 Slint 窗口从同一个主题描述生成颜色、字号、
圆角和间距常量；页面可用不同布局，但不能各自发明颜色、字体或按钮样式。

## 三个界面

### 任务栏

默认完整结构为：`同一水域内的 Weekly 前景浪 + 5h 底浪 + 水域内文字阅读区`。

- 不显示任何状态文字、状态灯、当前任务 Token、API 可用或数据源名称；
- 流式胶囊显示主要窗口的剩余百分比。5h 存在时作为同一水域的紫色底浪叠在 Weekly
  前景浪之下；5h 不存在时只显示 Weekly 主浪，不留占位；
- 余额的短格式最多两位小数，自动收紧，不占用多行；
- 主/副屏、左右停靠、TrafficMonitor 偏移及通知区保留区域仍由定位器计算；组件本身
  的实色背景不越界，不遮挡其他任务栏图标；
- 左键打开/关闭详情卡；右键打开托盘/上下文菜单；鼠标悬停提供精确百分比和余额
  提示；所有可点击区域返回 `HTCLIENT`。

按可用宽度使用同一组组件折叠，而不是缩小字体：

| 可用宽度 | 任务栏内容 |
| --- | --- |
| 460 px 以上 | 单一水域：今日、缓存、条件 Credits、Weekly/5h 双层叠浪与两项百分比。 |
| 340–459 px | 单一水域：今日与缓存缩为紧凑标签；Credits 只在触发条件满足时出现。 |
| 240–339 px | 单一水域：仅双层叠浪与两项百分比；不缩小字体。 |

“今日消耗”和“缓存命中率”直接置于水域上部的阅读安全区，波峰不得压住文字；
Credits 只在订阅耗尽且可用时出现。设置页允许调整今日与缓存两项的相对顺序，但不能
拆散两层叠浪的 Weekly/5h 关系。

### 自动上浮快览

恢复旧胶囊的“消耗时上浮”逻辑：可信 Token 用量相对上次快照正向增长，或官方额度
在更高 revision 中真实下降时，自动显示在任务栏正上方约 4 秒；首帧、旧 revision、
额度重置、单纯状态变更、轮询失败和缓存重放均不得弹出。频繁增量合并并延长现有计时器，避免闪烁和连续弹窗。

快览沿用用户选定的紧凑上浮卡片样式，但将“本次消耗”改名为“用量摘要”：`今日消耗 ·
缓存命中率 · 本轮预估金额 · 额度重置倒计时`。不出现累计“当前任务 Token”；若官方
未提供费用估算，金额为 `--` 而不是由 Credits 推算。

### 详情卡片

详情卡片采用用户选定的大卡片骨架：顶部为小型独立额度模块和今日 Hero，下方为两列
数据区；额度模块不得横跨整张卡片、不得挤压数据内容。

| 区域 | 内容 |
| --- | --- |
| 顶部 Hero | `今日消耗`（Token 大数字）+ 数据来源 / 最后刷新时间。 |
| 顶部小额度模块 | 单一水域双层叠浪、Weekly/5h 百分比、`5 小时重置于`与`每周重置于`的精确本地日期时间。 |
| 今日构成 | 今日输入、今日缓存、今日输出、缓存命中率；数据不完整时是 `--`。 |
| 估算金额 | 仅官方线程用量明确返回 USD 微单位时显示“本轮预估 $x.xx（估算，非账单）”；否则 `--`。 |
| 历史总消耗 | 官方 `lifetime_tokens`；不再显示无法可靠维护的“历史使用曲线”。 |
| 余额与重置卡 | `Credits 余额`（两位小数原值）、重置券可用次数和最早精确到期时间；任务栏仍只在订阅耗尽后显示余额。 |
| 底部 | 数据新鲜度与隐私说明；不再有最近活动、并发任务、错误率、当前任务 Token 构成或本机任务明细。 |

详情允许点击刷新与打开设置；其背景也是实体深色，不让鼠标穿透。

### 设置窗口

设置页使用按需启动的 Rust + Slint 软件渲染窗口，不使用系统主题控件；全部采用显式
深色调色板和 `Microsoft YaHei UI`，避免此前浅底浅字、残影和点击失效问题。分为三页：

1. **任务栏布局**：显示器、左右停靠、宽度、安全间距、TrafficMonitor 偏移；
2. **显示与动效**：叠浪额度、今日消耗、缓存命中率可见性，减少动画及自动快览触发
   规则说明；
3. **诊断与关于**：日志等级、CLI 路径、数据来源、无敏感信息的状态诊断。

保存采用原子写入 + 无敏感重载标记；常驻程序下一轮轮询即时应用位置、显示和动画。

## 验收标准

1. Credits 显示为“Credits 余额”，数值不超过两位小数；USD 仅显示官方明确返回的估算值，二者不换算；
2. 当前任务 Token 在任务栏、详情 Hero、主图表、健康行中均不存在；
3. 任意一条真实长运行 `inProgress` 任务超过 30 秒仍显示非灰活动灯，终态后正确回绿/
   灰；
4. 任务栏实体组件可左/右键点击，且不覆盖通知区、TrafficMonitor 或其他任务栏图标；
5. 可信 Token 正向增量或更高 revision 的官方额度下降触发一次自动上浮快览，约 4 秒后消失且不会连续闪烁；
6. 流式进度在 100%、150%、200% DPI 下完整显示，5h 缺失时无留白；
7. 设置窗口在 100%、150%、200% DPI 下文字可读、控件可点、滚动无残影；
8. `cargo fmt --check`、workspace tests、workspace Clippy 和 release 构建通过，并以真实
   官方登录和模拟数据各验收一次。
