# ADR-0004：采用 WebView2 承载任务栏流体视觉

**状态：已接受，WebView2/WebGL POC 已通过，待接管生产任务栏**

## 背景

任务栏、消耗弹窗、详情卡片与设置页的视觉已在 `prototypes/` 中完成确认。核心
效果是 WebGL2 着色器驱动的流体前沿、连续流光、半透明毛玻璃和 CSS 动画。此前
Direct2D 原生绘制只能近似表现，无法稳定达到确认稿的质感和帧连续性。

## 决策

- 常驻采集、官方 API、SQLite 只读后备、DPAPI、配置、日志和任务栏定位仍为 Rust。
- 任务栏、消耗弹窗、详情卡片和设置页使用同一套本地 HTML/CSS/JavaScript 资产；
  Windows 侧用 WebView2 承载，不使用 Electron，不捆绑 Chromium。
- 宿主只向页面发送 `TaskbarSnapshot` 这类脱敏 JSON；页面不能读取文件、网络、
  `auth.json`、SQLite 或系统 API。
- 页面通过受限的消息枚举请求操作（打开详情、刷新、打开设置、退出），宿主逐项
  校验；不提供任意脚本执行和通用文件访问桥接。
- WebView2 使用独立、可清理的应用数据目录；在首次初始化时关闭开发者工具、默认
  右键菜单和不需要的浏览器能力。

## 交付顺序

1. 在不改动生产任务栏的前提下完成 WebView2 静态资产与宿主 POC；验证 WebGL2、
   60 FPS、透明合成、缩放、窗口大小改变和安全消息桥。**已完成基础 POC：**
   `--webview-preview` 将确认稿及共享视觉契约内联进 WebView2，实际截图确认
   WebGL 流体胶囊、中文字体和弹窗可正常渲染；透明合成、缩放和真实帧率将在
   Explorer 任务栏子窗口接管时继续验收。
2. 以当前 Explorer 任务栏 child HWND 替换 Direct2D 渲染面；同一 `TaskbarSnapshot`
   驱动已确认的双额度胶囊。
3. 迁移消耗弹窗、详情卡片，再迁移按需打开的设置窗口；所有页面共享视觉变量。
4. 删除不再使用的原生自绘路径和重复的预览模型，避免双实现持续漂移。

## 资源与兼容性

- WebView2 使用 Windows 已安装的 Evergreen Runtime；应用安装包不嵌入浏览器内核。
- Rust 可执行文件只加入 WebView2 COM 绑定和本地静态资源，预计不会达到 Electron
  级别的体积或内存占用。
- 首次创建浏览器进程会产生短时内存开销；设置窗口关闭后销毁，任务栏只保留一个
  小视图。运行时不在动画帧执行网络、SQLite 或磁盘写入。
- 缺少 WebView2 Runtime 时显示明确的安装提示并保留托盘退出入口，不能静默降级为
  与确认稿不一致的旧绘制。

## 验收标准

- 真实 `TaskbarSnapshot` 的状态、5 小时/7 天/余额条件、今日 Token、缓存命中率在
  页面中正确显示；没有 5 小时额度时不留下空白层。
- WebGL2 动画独立于数据刷新，目标为显示器刷新率上限（通常 60 FPS）；静态/减少
  动效选项可停止连续帧。
- 透明未使用区域不被黑色预乘边缘污染；100%、150%、200% DPI 截图与确认稿对比。
- UI JSON、页面 console、结构化日志和缓存文件均不出现 API Key、账户原文、Prompt、
  完整线程标识或 SQLite 正文。
