# 详情卡片布局约束（v2）

> 本文是详情卡片下一轮实现的唯一版式约束。它以用户已确认的浅色玻璃视觉和“今日消耗主方块 + 右侧四项 2×2”要求为准，不沿用早期为适配深色界面而写的旧约束。

## 已定位的问题

当前嵌入版在副屏 150% DPI 下把五张摘要卡排为三列、两行，并将小卡强制压到 `92px` 高。实际 WebView CSS 视口比窗口物理尺寸窄，右侧内容被裁切；后续为了塞进内容又缩小字号。因此问题不是数据缺失，也不是用户要求“更窄”导致，而是**布局模型和 DPI 视口不匹配**。

## 固定版式

1. 外层详情卡保持浅色毛玻璃、圆角、无黑色外描边；整体宽度必须比此前 960px 宽版更收窄，不能用扩大窗口来避免裁切。
2. 顶部保留“官方账户 / 数据更新时间”和必要操作；操作区在窄视口可收缩，不能挤压正文。
3. 左侧为紧凑账户栏：5 小时额度（存在时）、7 天额度、邮箱、订阅方案、官方来源、余额/今日余额消耗、重置卡及精确到期时间。没有 5 小时额度时整块隐藏而非显示空卡。
4. 右侧第一行摘要固定为一个 `1 + 4` 结构：
   - 左侧：`今日消耗` 大方块，视觉上接近正方形，显示总 Token、输入、缓存输入、输出；
   - 右侧：`缓存命中`、`估算金额`、`今日余额消耗`、`本机历史消耗` 四张短卡，严格 2×2；
   - 五项必须同时完整可见，不能裁切、横向溢出或以省略号替代数值。
5. “今日消耗趋势”位于摘要下方，宽度为内容栏的约 65–72%，不再横跨到卡片最右侧；可切换今日 / 本机历史 / 金额，曲线保持平滑交互。
6. 当前任务 Token 不再出现。官方没有提供的金额/余额含义不臆造：显示 `--` 并给出明确来源说明。

## 字体与密度基线

- 以早期可读版本为基线：主方块主数字约 `28–32px`，小卡数值约 `17–18px`，标签 `10–11px`，辅助文字 `9.5–11px`。
- 禁止为了适配而继续缩小上面的基线。应先缩减留白、收窄左栏、让操作区收缩，并让右侧四项使用独立 2×2 网格。
- 主方块的输入、缓存输入、输出均需完整显示，不能因装饰图形盖住文字。

## 数据连通约束

- 今日 Token（输入 / 缓存输入 / 输出）、缓存命中、本机历史与趋势：来自只读本机账本与已确认 Token；未知时显示 `--`。
- 订阅额度、重置时间、官方余额/重置卡：来自官方登录已授权数据；余额原始单位不擅自换算美元。
- 估算金额只在官方明确提供计价依据时显示，否则 `--`。
- 不增加高频网络请求；页面刷新只消费已汇总的快照。

## 本轮验收标准

1. 在副屏 150% DPI 的真实 WebView 弹窗截图中，五张摘要卡、输入/缓存输入/输出、趋势卡均完整显示，无横向裁切。
2. 对比早期可读截图，主数字和小卡数字不更小；整体卡片却不采用此前 960px 宽版的过宽布局。
3. 无数据、无 5 小时额度、订阅耗尽后显示余额三种模拟数据都不产生重叠、空白大区或伪造值。
4. 只在上述截图验收通过后，再继续恢复弹窗与设置页的实际集成。
