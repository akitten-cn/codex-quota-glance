# Codex Taskbar 可视化验收里程碑 V2

> 状态：实施与实机验收目标  
> 更新日期：2026-08-23  
> 适用模式：Codex 官方登录 / New API，两套数据域共用视觉系统但不混合语义

## 1. 目标

本里程碑要交付的不是一个只有圆环的技术演示，而是一套可在真实 Windows 任务栏中长期使用、能够直接评价视觉效果的组件：

- 常驻任务栏的紧凑摘要，清晰显示主要剩余额度、API 活动状态和可配置关键信息；
- 点击摘要后，在该组件正上方打开浅色宽幅双栏详情卡片；
- 悬停摘要时升起独立的 Token 快览滑块；
- 对 New API / API-only 数据源使用准确的状态语义，不再以官方登录态作为可用性前提；
- 在 100%–200% DPI 下保持清晰、可读、不过度拥挤。

## 2. 两种界面必须明确区分

### 2.1 任务栏常驻组件

任务栏组件只承担“扫一眼即可理解”的摘要职责，不把所有详情挤入约 32–40 DIP 高的任务栏：

- 左侧为活动状态灯；
- 中部为紧凑双圆环，圆心显示主要剩余百分比；
- 右侧为 1–2 行可配置摘要，例如状态、Token、5h、Weekly；
- 整体透明融入任务栏，不绘制大面积独立卡片背景；
- 整个有效区域可点击，具有明确的 hover/pressed 反馈；
- 单击只负责打开或关闭详情卡片。

### 2.2 点击详情卡片与 Token 快览滑块

用户所说的“和之前胶囊的显示一样”，指点击任务栏组件后出现的独立详情卡片，而不是把任务栏常驻组件本身重新做成大胶囊。

详情卡片应：

- 紧贴任务栏组件，在其正上方浮出；
- 采用用户参考图中的浅色近白背景、宽幅双栏数据表、细分隔线、柔和阴影和清晰的信息层级；
- 左栏展示账户与额度，右栏展示 Token 活动或今日 API 统计；
- 右上角使用 `官方登录` 或 `API 模式` Badge，不能只靠标题猜数据来源；
- 不使用系统 `MessageBox`、屏幕中央普通 Dialog 或独立主窗口替代；
- 不在系统任务栏产生第二个按钮，也不进入 Alt+Tab；
- 点击外部、按 Esc 或再次点击任务栏摘要时关闭。

两者的关系是“任务栏摘要 → 上浮详情”，而不是两个并列应用窗口。

Token 快览滑块与详情卡片是两个独立层级：

- 鼠标进入任务栏组件时，在其上方升起约 46 DIP 高的深色窄条，五列使用紧凑等宽布局；
- 官方登录模式固定展示最近一次 Turn 的 `输入 / 缓存 / 输出 / 命中 / 本次`；
- 推理 Token 与线程累计属于诊断明细，只保留在详情卡，不占快览首屏；没有实时最近 Turn 时五项统一显示 `--`，不得用线程累计冒充“本次”；
- 滑块不抢焦点、不进入 Alt+Tab，鼠标离开后关闭；
- 单击任务栏时先关闭滑块，再打开详情卡片，二者不得重叠。

## 3. DPI 与坐标规范

- 所有布局常量均以 DIP 定义，禁止把字号、圆环半径和间距写死为物理像素。
- 运行时按任务栏所在显示器的实际 DPI 换算；组件跨屏或 DPI 改变后，重新创建字体、重新测量文字并重新布局。
- 验收覆盖 100%、125%、150%、175% 和 200% 缩放。
- 线宽小于 2 DIP 的元素应进行 pixel snapping，避免 100%/125% DPI 下发虚。
- 文本宽度必须用实际字体测量，不能用“字符数 × 固定宽度”估算。
- 测量样本至少覆盖 `100%`、`999.9K`、最长中文状态、5h/Weekly 最长格式。

## 4. 任务栏尺寸与字体

### 4.1 标准规格（任务栏可用高度约 36 DIP 或更高）

| 元素 | 规格 |
| --- | --- |
| 组件总高 | 36 DIP |
| 圆环占位 | 34 × 34 DIP |
| 主信息字体 | 13.5 pt，`Segoe UI Variable Text Semibold` |
| 次信息字体 | 11.25 pt，`Segoe UI Variable Text Regular` |
| 主信息行高 | 17 DIP |
| 次信息行高 | 14 DIP |
| 圆环与摘要间距 | 6 DIP |
| 左内边距 | 3–4 DIP |
| 右内边距 | 8 DIP |
| 摘要列间距 | 6–8 DIP |

字体回退顺序为 `Segoe UI Variable Text`、`Segoe UI`、系统默认 UI 字体。数字应使用 tabular numbers，以避免百分比或 Token 刷新时横向跳动。

### 4.2 32 DIP 高度降级规格

- 圆环缩至 30–31 DIP；
- 主信息不得小于 11 pt；
- 次信息不得小于 9.25 pt；
- 优先减少非必要间距或隐藏低优先级摘要，不通过缩到难以阅读的小字号来硬塞内容。

### 4.3 状态灯

- 实体直径 5–6 DIP；
- 光晕直径 10–12 DIP；
- 只有“正在请求/活跃”状态允许呼吸或光晕动画；
- 空闲状态低亮显示，连续错误使用橙/红色；
- 圆环本身不持续大范围发光，避免抢夺百分比的视觉焦点。

## 5. 双圆环

- 外环表示 Weekly，外径 34 DIP，中心线半径 15 DIP，线宽 2.0 DIP；
- 内环表示 5h，中心线半径 12.1 DIP，线宽 1.7 DIP；
- 两环边缘净间距约 1.05 DIP；在 100% DPI 下至少保留 1 个物理像素；
- 起点统一为正上方 `-90°`，顺时针绘制；
- 进度弧采用 round cap；
- 未用轨道透明度 22%–28%，有效进度弧不透明度 95%–100%；
- 进度值限制在 `0..100`，100% 应绘成完整环且不能出现零长度弧、缺口错位或重叠端点伪影；
- 两环在视觉上属于同一组件，禁止出现 2–3 DIP 的松散大间隙；同时不得粘连成单条粗环；
- 默认外环承担主百分比语义，内环作为次级额度；颜色需同时具备足够明度差，不能只靠相近色相区分。

阈值建议：剩余量大于等于 20% 使用正常蓝/青色，低于 20% 使用橙色，低于 10% 使用红色。阈值的最终含义应与“剩余百分比”一致，不得把已用百分比和剩余百分比混用。

## 6. 圆心百分比排版

圆心必须完整显示百分比，包括 `%`，不得裁切、变成省略号或压到圆环线上。

- `0%–99%`：数字 10 pt Semibold，百分号 7 pt Regular；
- `100%`：数字自适应到 8.5–9 pt，百分号约 6.5 pt；
- 数字与 `%` 使用两个 text run 组合排版，百分号基线可上移 0.5–1 DIP；
- 组合后的实际宽度不得超过内环孔径减 1.5 DIP；
- 若超宽，按 0.25 pt 逐级缩小，直到完整容纳；禁止裁切；
- 水平与垂直居中依据实际视觉包围盒，而不是仅按字体 ascent/descent 机械计算；
- 必须验证 `0%`、`8%`、`68%`、`99%`、`100%` 五组关键样本；
- 没有可靠额度时显示 `--`，不可伪造预览百分比进入生产模式。

## 7. 上方详情卡片

### 7.1 锚定和窗口行为

底部任务栏的默认定位：

```text
popup_x = widget_x + widget_width / 2 - popup_width / 2
popup_y = widget_top - 8 DIP - popup_height
```

定位后将窗口限制到当前显示器 work area 内，四周保留至少 8 DIP 安全距离。若任务栏位于屏幕顶部，则详情卡片显示在组件下方；左右任务栏按同样原则选择靠近工作区的一侧。

窗口实现要求：

- 使用无边框 popup/tool window；
- 不进入 Alt+Tab，不产生额外任务栏按钮；
- 弹出时维持 topmost，但不永久压住其他应用；
- 内部控件保持可点击，不可通过永久鼠标穿透来实现透明；
- 点击后 100 ms 内先出现卡片外壳或完整卡片，不能让用户误以为没有响应；
- 点击外部、Esc、再次点击摘要均能关闭。

### 7.2 视觉规格

| 元素 | 规格 |
| --- | --- |
| 卡片宽度 | 760 DIP |
| 卡片高度 | 472 DIP（官方卡片 V2；无 5h 时按内容动态收缩） |
| 与任务栏间距 | 8 DIP |
| 圆角 | 12–14 DIP |
| 内边距 | 16 DIP |
| 标题 | 15 pt Semibold |
| 卡片值 | 11–11.5 pt Semibold |
| 标签/说明 | 10.5–11 pt Regular |
| 普通详情行高 | 25–29 DIP |
| 分隔线 | 1 px，深色 12%–18% |
| 外边框 | 1 px，深色 16%–20% |
| 阴影 | 16–24 DIP 柔和阴影 |

推荐信息层级：

1. 标题区：账户/Provider 名称、活动状态、数据新鲜度与模式 Badge；
2. 左栏：账户身份、套餐、5h/Weekly、Credits、消费控制；
3. 官方模式右侧为宽幅 Token 用量仪表盘：当前任务累计、最近一次摘要、输入/输出/缓存/推理明细、互斥构成图和账户活动；左侧压缩为账户与额度背景。New API 仍展示今日统计与账户/Key 分区；
4. 底部：各区域数据源说明，明确官方、本机、第三方边界。

## 8. 双模式数据与展示语义

### 8.1 官方登录模式

官方卡片的数据优先级由 Codex App Server Schema 决定，社区项目只用于信息层级、缓存与视觉参考。

| 信息 | 首选来源 | 展示与降级 |
| --- | --- | --- |
| 账户类型/邮箱/方案 | `account/read` | 邮箱只进入 UI 前掩码；`account=null` 时结合 `requiresOpenaiAuth` 解释，禁止读取 `auth.json` 补齐 |
| 认证变化 | `account/updated` | 收到后立即重新执行完整 `account/read`，不沿用旧身份 |
| 5h / Weekly | `account/rateLimits/read` | 优先 `rateLimitsByLimitId.codex`，回退 legacy `rateLimits`；按 300/10080 分钟识别，缺失窗口不画假圆环 |
| Credits | `RateLimitSnapshot.credits` | `null` 隐藏；unlimited 显示“无限”；余额保留后端字符串，不自行添加货币符号 |
| 消费控制 | `individualLimit` / `spendControlReached` | 单独显示个人上限和触达状态，不与 5h/Weekly 合并 |
| 重置额度 | `rateLimitResetCredits` | 只读显示可用次数和最近到期；首版不调用 consume 写接口 |
| 账户 Token 活动 | `account/usage/read` | 展示累计、单日峰值、最近日桶、连续天数；老版本不支持时隐藏整区 |
| 当前线程 Token | `thread/tokenUsage/updated` | 与账户活动分区；展示输入、缓存、输出、推理和总计 |
| 活动状态 | App Server 生命周期通知，SQLite freshness 后备 | 额度接口失败不得把活动状态重置为 Unknown |

官方数据新鲜度固定为三态：

- `官方实时`：本轮 App Server 完整读取或通知成功；
- `官方缓存 · N 分钟前`：连接中断但保留最后成功快照；
- `官方数据不可用`：尚无任何可靠快照。

额度重置时间已经过去、但后端尚未刷新时显示“等待刷新”，不能在本地自动恢复成 100%。官方账户级 Token 与本机线程 Token 不相加，也不能把 SQLite 本机统计冒充官方 lifetime。

### 8.2 New API / API-only 状态语义

当前模式通过 New API 获取数据，不具备也不需要官方账号登录态。因此 UI 不得把“未登录”“官方登录状态未知”作为主状态，也不能因为没有官方 rate-limit 数据就判定应用不可用。

应展示能够由 API 客户端和本地请求生命周期可靠判断的状态：

- `API 可用`：最近请求成功；
- `请求中`：当前存在未结束请求；
- `空闲`：当前无请求，但 API 配置可用；
- `限流`：服务返回 rate-limit 响应；
- `认证失败`：API key、endpoint 或相关凭据无效；
- `网络不可用`：连接、DNS、超时等网络错误；
- `额度数据不可用`：API 正常但数据源没有提供 Weekly/5h 额度。

状态灯语义：

- 请求中：蓝色呼吸；
- 最近 30 秒成功调用：绿色常亮或轻微光晕；
- 空闲：低亮灰蓝；
- 限流/认证失败/连续错误：橙色或红色。

详情区必须注明数据来源为 `New API`。账户余额、Key 额度、今日 API 统计不能写入官方 5h/Weekly 圆环；任务栏仍可展示 API 活动、Token 和其他真实摘要，不得用模拟值填补。

账户、Key 与今日日志分别维护最近成功值：本轮失败但存在缓存时，Header 显示“API 使用缓存”或“API 部分实时”，健康条显示紧凑的缓存年龄与当前失败原因，例如“缓存3分 · 限流”。Header 的更新时间取最近一次成功时间，不使用失败轮询时间冒充数据更新时间。

### 8.3 缓存与持久化边界

- 内存中分别维护 `official`、`provider`、`thread usage` 三套时间轴；
- 磁盘缓存按模式、Provider、`CODEX_HOME` 和安全身份指纹隔离；
- 只保存脱敏账户摘要、完整额度快照、账户聚合 Token 与时间戳；
- API key、access token、邮箱原文、prompt、reasoning、`auth.json` 内容永不进入缓存和日志；
- 稀疏通知只在内存合并，下一次完整 read 原子覆盖；
- 首版可以仅内存保留最后成功值；官方真实日桶已支持五日轻量趋势，完整历史浏览器仍留到后续持久化里程碑。

## 9. 视觉验收标准

以下项目必须通过真实 Windows 任务栏运行和截图验证，而不只依赖单元测试：

### 9.1 任务栏摘要

- 100%、125%、150%、175%、200% DPI 下字体视觉大小一致且清晰；
- 主信息明显大于 V1，中文与数字在正常观看距离下可读；
- 组件在典型任务栏高度内垂直居中，无顶部/底部裁切；
- `0%`、`8%`、`68%`、`99%`、`100%` 均完整显示；
- 双环边缘间距约 1 DIP，既不松散也不粘连；
- 100% 完整环无明显接缝、零弧或端点凸块；
- 右侧内容使用真实字体测量，不裁切最长中文状态和数值；
- hover、pressed、活动灯状态可以从截图或录屏中区分；
- 没有额度数据时显示 `--`，生产模式中不出现预览假值。

### 9.2 详情卡片

- 单击任务栏摘要后，卡片在 100 ms 内出现在组件正上方约 8 DIP；
- 卡片中心优先与任务栏组件中心对齐，靠近屏幕边缘时自动夹入当前显示器 work area；
- 顶部、底部、左侧、右侧任务栏均不会让卡片跑出屏幕；
- 卡片为浅色宽幅双栏圆角信息面板，不是胶囊、系统 MessageBox 或居中 Dialog；
- 卡片不产生额外任务栏按钮、不进入 Alt+Tab；
- 内部刷新/设置等入口可点击，点击外部、Esc 和再次点击均可关闭；
- 标题、双栏数据、状态说明和来源脚注具有清晰视觉层级；
- 官方模式和 New API 模式使用同一视觉语言，但字段、缓存和状态绝不串值；
- API-only 状态文案准确，不出现误导性的“官方未登录”。

### 9.3 验收产物

- 至少提供 100% DPI 的任务栏静态态、hover 态、详情卡片截图；
- 至少提供 150% 或 200% DPI 的任务栏与详情卡片截图；
- 提供 `100%`、无额度 `--`、请求中和 API 错误四种关键状态截图或录屏帧；
- 截图来自真实任务栏运行，不以独立预览窗口代替最终实机验收；
- 自动化测试、Clippy/静态检查和 Release 构建全部通过后，才进入用户视觉评价阶段。

高 DPI 弹窗使用两层约束：窗口层按当前显示器 `rcWork` 与 DPI 边距等比缩小最终像素尺寸，渲染层再把 `880×590 DIP` 详情设计稿或 `424×46 DIP` 快览设计稿整体缩放。这样在 150%/200% 缩放、小工作区和负坐标副屏上不会只夹紧坐标却继续裁掉内容；空间充足时绝不放大。
