# 官方登录的本机今日用量账本

## 目标

在官方 Codex App Server 没有回传当日 Token 明细时，为任务栏和详情卡提供**本机捕获的今日 Token 消耗**。它是补充来源，不把订阅额度、Credits 或累计线程 Token 误当作今日消耗。

## 数据边界

- 只读 `%USERPROFILE%\\.codex\\state_*.sqlite` 的结构化字段：线程稳定标识、`updated_at`、`tokens_used`、`archived`。
- 不读取 `thread_items.item_json`、rollout、提示词、工具参数、文件路径或线程标题。
- 线程标识只在内存中参与增量匹配；持久化前使用不可逆的稳定摘要，绝不写入日志、详情卡、导出文件或设置文件。
- 仅接纳 `tokens_used` 的正向变化；新线程、计数回退、归档和应用重启后的第一帧都建立基线，不计入消耗。

## 统计语义

1. 某线程第一次被观察到时：仅建立基线，避免把历史线程累计量算到今天。
2. 同一线程累计量增加时：增加量写入当天桶，并记录小时桶用于平滑趋势。
3. 午夜后：内存中保留最近 35 天桶；新日期从零开始。
4. App Server 提供权威 `today` 时：优先显示官方数值；本机账本作为诊断和缺失时的替代来源。
5. 本机账本第一次运行前无法追溯当天已经发生的旧消耗，界面必须标明“本机捕获”，不能声称完整的官方日账单。

## 磁盘预算与可靠性

- 轮询只在现有的 5 秒 SQLite 后备节奏内执行，不新增数据库连接循环。
- 当前版本先只在内存累计：不产生任何账本写入，也不会新增磁盘尖峰。重启后首帧重新建立基线。
- 后续持久化必须至少间隔 60 秒且存在新增量时才写一次；退出时最多尝试一次最终写入，并使用临时文件 + 原子替换。单文件限制为 64 KiB，自动裁剪过期天/小时桶。
- 任何读取、解析、写入失败都保持监控进程可用，详情降级为“本机统计暂不可用”。
- 不把计数变化写入运行日志；Debug 日志最多记录聚合结果和失败类别。

## 验收

- 首帧与重启后不产生虚假的今日消耗。
- 同一累计值、倒退值、旧时间戳不增加统计。
- 正向增量只记一次，跨午夜进入新桶。
- 60 秒内多次更新最多产生一次持久化写入。
- 今日 Token、缓存命中无法得到时显示明确空状态，不显示伪造的 `--` 数值卡。
