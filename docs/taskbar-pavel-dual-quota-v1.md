# Pavel 双额度任务栏设计与验收

## 目标

将任务栏收敛为一枚可点击的深色椭圆胶囊。它覆盖官方登录下用户在任务栏需要立即判断的全部信息：5 小时额度、Weekly 额度、今日 Token、缓存命中、订阅额度耗尽后的余额，以及 Codex 活动状态。

本阶段只处理任务栏本体与其数据链路；详情卡、消耗快览、设置页面保持现状，避免再次把多个模块同时改坏。

## 视觉规则

### 1. 一个水域，不拆成两条进度条

- 外层胶囊是唯一的圆角轮廓。
- **已消耗比例 = `100 - remaining_percent`**，从左到右铺开；右侧数字仍显示“剩余百分比”。
- Weekly 是前景水层，颜色由活动状态决定；5 小时存在时作为较暗的紫蓝底流，二者裁剪在同一枚胶囊中，不能上下分栏，也不能产生第二个背景轮廓。
- 两层的右侧都使用连续、近似垂直的流体前沿；填充层本身不允许有右端半圆。
- 5 小时窗口权威地 `Absent` 时，底流和“5小时 xx%”同时完全隐藏，Weekly 自动成为唯一流层；`Unknown` 不能冒充缺失或 0%。

### 2. 文字锚点与显示优先级

| 区域 | 5 小时存在 | 5 小时缺失 |
| --- | --- | --- |
| 左上 | `今日 42.8K` | `今日 42.8K` |
| 左下 | `缓存 74%` | `缓存 74%` |
| 中部 | 仅在规则满足时显示 `余额 12.50` | 同左 |
| 右上 | `Weekly 68%` | `Weekly 68%` |
| 右下 | `5小时 43%` | 不占位 |

任务栏不显示“未知状态”“Token 暂无数据”“API 可用”“当前任务 Token”等技术性文字。今日没有可靠统计时，显示 `今日 --` 与 `缓存 --`，不从线程累计或历史日桶虚构数字。

### 3. 余额（Credits）规则

`Credits` 是官方返回的独立余额单位，不能默认当成美元，也不能自行换算。可解析数值仅格式化为两位小数。

仅在以下条件同时满足时显示在胶囊中部：

1. 官方返回启用、非无限、带余额的 Credits；且
2. 有 5 小时窗口时，5 小时额度已权威地耗尽；或
3. 官方明确没有 5 小时窗口时，Weekly 已权威地耗尽。

除此以外余额只留在详情卡，避免用户误以为订阅额度和余额会同时扣除。

### 4. 状态颜色与过渡

没有独立状态灯，Weekly 前景水层承担状态提示。新色以一股新流从左到右覆盖旧色；额度前沿位置不因状态变化而改变。

| 状态 | 前景色 | 动画 |
| --- | --- | --- |
| 空闲 / 已完成 | 翡翠绿 | 已完成短暂流动三秒后，空闲保持极慢纹理 |
| 推理中 | 蓝紫 | 持续、缓慢的染料流动 |
| 执行中 / 审阅中 | 青蓝 | 持续、缓慢的染料流动 |
| 等待用户 | 琥珀 | 静态或极低速纹理 |
| 失败 | 低饱和红 | 静态纹理 |
| 数据不可用 | 中性灰蓝 | 无高光、无伪运行感 |

动效目标为稳定 60 FPS；使用连续的单调时间值，不使用 0..1 的短周期取模，以免看到循环卡顿或回到起点。

## 数据来源与真实性

| 显示项 | 优先来源 | 降级行为 |
| --- | --- | --- |
| 5 小时 / Weekly | 官方 Codex App Server 的完整额度快照 | `Unknown`；绝不显示旧额度为实时 |
| 今日 Token | App Server 的日聚合；缺失时只读 SQLite 的本机增量账本 | 本机值标记为部分捕获；无增量即 `--` |
| 缓存命中 | 同一份可靠 Token 明细中的 `cached_input / input` | 明细不完整即 `--` |
| Credits 余额 | 官方账户快照 | 不猜测货币、不将缺失显示为零 |
| 状态 | App Server 的具体活动事件；否则只读 SQLite `thread_history` 元数据 | 数据库不可读为中性灰蓝 |

SQLite 仅以只读方式访问结构化元数据和 Token 计数；不读取 prompt、线程标题、命令正文或 `item_json`，也不向 Codex 数据库写入任何内容。

## 验收矩阵

### 模型测试

1. 5 小时存在：两层共享同一水域，二者都以已消耗比例定位前沿。
2. 5 小时权威缺失：只绘制 Weekly，不留第二层/第二行/透明占位。
3. 5 小时耗尽且 Credits 有效：中部显示 `余额 x.xx`。
4. 5 小时缺失且 Weekly 耗尽：中部显示 `余额 x.xx`。
5. 非耗尽、额度未知、Credits 未启用、无限或余额缺失：中部不显示 Credits。
6. 今日 Token、缓存命中分别测试官方聚合、本机部分增量与不可用三种口径。
7. 7 个活动状态分别产生既定前景色；`Executing → Idle` 的颜色替换不改变额度前沿。

### 运行时与截图

1. 为上述五种额度组合提供只使用固定脱敏数据的预览模式，逐项截图。
2. 启动真实官方登录运行，确认至少一份官方额度快照；不将 fixture 当作真实数据。
3. 在真实 Codex Turn 中记录“推理/执行/完成后空闲”三个时刻的脱敏活动枚举与截图。
4. 以 60 FPS 运行 30 秒：无可见周期跳变、无 CPU 忙等、无每帧磁盘写入。
5. `cargo fmt --check`、相关单元测试、Clippy 通过后，才将此渲染方案用于默认任务栏。
